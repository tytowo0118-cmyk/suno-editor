# analyzer 容器专用依赖 —— 主后端镜像（requirements.txt）不装这些。
# 为什么隔离：torch+cpu 轮子实测 146.5 MB、htdemucs 权重 80.2 MB，且 madmom / natten 在 PyPI 只有
# sdist 需要 gcc/Cython 现场编译；塞进热挂载 + --reload 的开发镜像会让每次改依赖变成十分钟构建。
#
# 全部 pin 死：这里每一个版本都影响推理数值，浮动升级换来的不是新功能而是「上次标定过的精度不再成立」。
# pin 的组合在本机平台（linux/aarch64 + cp311）逐个查过 PyPI 元数据，编译型依赖都有现成轮子：
# torch/torchaudio 2.1.2、numpy 1.26.4、scipy 1.13.1、numba 0.59.1 + llvmlite 0.42.0、
# scikit-learn 1.4.2、matplotlib 3.8.4、lameenc 1.9.0 全部提供 manylinux aarch64 轮子；
# 只有 natten 0.14.6 与 madmom@main 需要镜像里 build-essential 现场编（见 Dockerfile.analyzer）。
#
# torch 与 madmom 不在这里，由 Dockerfile.analyzer 分层装（层序有依赖关系，不能合并）。
numpy==1.26.4  # 与应用层同 pin：librosa / madmom / torch 都吃 1.x，被顶到 2.x 会静默改变 DSP 数值
scipy==1.13.1  # allin1 postprocessing 用 argrelextrema / interp1d；1.13 是 requires numpy<2.3 的最后一线
librosa==0.10.2  # 1.0.0 要求 Python>=3.12，py3.11 装不上；0.10.2 经 postprocessing/helpers.py 进入推理路径
soundfile==0.12.1  # 注意：只有 x86_64 轮子自带 libsndfile.so，aarch64 轮子没有 → 系统库由 Dockerfile.analyzer 层 6 apt 装 libsndfile1
numba==0.59.1  # librosa 的传递依赖，要求 numpy>=1.22,<1.27 —— 这条上限反过来验证了 1.26.4 的选法
llvmlite==0.42.0
scikit-learn==1.4.2
tqdm==4.66.4
matplotlib==3.8.4  # allin1.analyze 在模块导入期就 from .visualize import visualize，躲不掉

omegaconf==2.3.0
huggingface-hub==0.23.4  # 权重下载：hf_hub_download(repo_id='taejunkim/allinone')
demucs==4.0.1  # allin1/analyze.py 用 subprocess `python -m demucs.separate --name htdemucs`，无条件执行
lameenc==1.9.0  # demucs 声明 lameenc>=1.2；1.2.0 只发到 cp37m 为止，py3.11 必须取 1.4+ 才有 aarch64 轮子
allin1==1.1.0  # 权重来自 huggingface-hub 的 taejunkim/allinone；其 requires_dist 在 Linux 上不装 natten，由镜像层显式钉 0.14.6
